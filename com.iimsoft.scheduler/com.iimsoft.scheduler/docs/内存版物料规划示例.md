# 内存版物料规划示例

## 概述

内存版物料规划功能提供了一个无需数据库依赖的演示程序，用于多日物料需求预测和生产计划制定。该功能结合了现有的TOC瓶颈识别逻辑和NSGA-II多目标优化算法。

## 特性

- **无数据库依赖**: 完全基于内存数据结构，无需PostgreSQL连接
- **TOC瓶颈分析**: 使用负载因子、利用率因子和换线因子识别瓶颈资源
- **NSGA-II优化**: 多目标优化，平衡完工时间、总延迟和库存波动
- **灵活配置**: 支持自定义规划周期、物料需求和生产能力
- **控制台输出**: 显示优化进度和帕累托前沿结果

## 运行方式

### 编译项目
```bash
cd com.iimsoft.scheduler
mvn compile
```

### 运行内存版物料规划演示
```bash
java -cp target/classes com.iimsoft.scheduler.v5.material.MaterialPlanningApp
```

### 运行原有数据库版本（需要数据库连接）
```bash
java -cp target/classes com.iimsoft.scheduler.v5.MainApp
```

## 数据模型

### MaterialDemand - 物料需求
- `materialId`: 物料ID
- `date`: 需求日期
- `quantity`: 需求数量

### MaterialDefinition - 物料定义
- `materialId`: 物料ID
- `resourceId`: 生产资源ID
- `ratePerHour`: 每小时生产率

### MaterialCapacity - 资源产能
- `resourceId`: 资源ID
- `date`: 日期
- `availableHours`: 可用小时数

### MaterialPlanConfig - 规划配置
- `startDate` / `endDate`: 规划时间窗
- `demands`: 物料需求列表
- `definitions`: 物料定义列表
- `capacities`: 资源产能列表
- `initialInventory`: 初始库存

## 算法流程

1. **虚拟工单生成**: 将物料需求转换为虚拟工单和路线工步
2. **瓶颈识别**: 使用TOC分析识别瓶颈资源
3. **NSGA-II优化**: 生成帕累托前沿解集
4. **目标计算**: 计算完工时间、总延迟和库存波动

## 输出解释

### 瓶颈分析
```
Resource MACHINE_001: Load=0.255, Util=0.700, Changeover=0.750, Score=0.438
Resource MACHINE_002: Load=0.071, Util=0.700, Changeover=0.000, Score=0.253
Identified bottleneck: MACHINE_001 (score: 0.438)
```

- **Load**: 负载因子（需求时间/可用时间）
- **Util**: 利用率因子（默认0.7）
- **Changeover**: 换线因子（物料切换频率）
- **Score**: 综合评分（Load×0.6 + Util×0.3 + Changeover×0.1）

### 帕累托前沿
```
Solution 1: [1760122740, 2527627, 4866.67]
```
格式：[完工时间(秒), 总延迟(秒), 库存波动]

## 技术架构

### 核心接口
- `ObjectiveEvaluator`: 目标函数评估接口
- `IRouterStepProvider`: 工艺路线提供接口

### 新增组件
- `VirtualOrderGenerator`: 虚拟工单生成器
- `InMemoryLoader`: 内存数据加载器
- `InMemoryBottleneckAnalyzer`: 内存瓶颈分析器
- `InMemoryObjectiveCalculator`: 内存目标计算器

### 兼容性
- 原有`MainApp`和`ObjectiveCalculator`保持不变
- `NSGA2Optimizer`通过接口重构保持向后兼容
- `SchedulingEngine`新增构造函数重载支持内存数据源

## 注意事项

- 内存版本使用简化的换线计算（基于时间顺序的物料切换）
- 利用率因子使用默认常量0.7
- 虚拟工单每个物料每日期生成一个工单
- 目标函数中的库存波动计算所有物料的总库存变异
